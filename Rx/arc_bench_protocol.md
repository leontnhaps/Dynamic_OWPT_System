# 실험 2 · 등각속도 반원 운동을 재현한 Rx의 광명령 보정과 PV 전압 비교

## 먼저 할 시험 · 고정각에서 광명령을 몇 번 받는가

정면에서 실시한 7속도 시험의 최단 비트 길이는 **12 ms(83.33 bit/s)**였다. 이번에는 같은 비트 길이로 반원 실험에 쓰는 **순번과 CRC가 있는 실제 명령**을 보낸다. Rx는 지정 자세를 유지하며 명령을 읽는다. 수신한 명령 때문에 Pan이 움직이면 한 각도의 성공률을 구할 수 없다.

1. 고정 광원과 Rx의 위치, 높이, 주변광, 부하를 유지한다. 먼저 아래의 **발판과 시작 방향**대로 Pan 180°·Tilt 20°에서 셀 앞면을 광원과 정면으로 맞추고 발판 위치를 표시한다. 이 자세를 입사각 오프셋 0°로 쓴다. 각도는 서보 명령 기준이다.
2. PC와 Rx 모두 이 브랜치를 업데이트한다. PC OOK 탭의 기존 **Pi SSH 연결**은 해제한다. Rx에서 처음에는 `python3 -m Rx.angle_reception --angle 0 --pair a12-000`을 실행한다. `START`로 자세를 맞춘다. Rx가 전압 기록을 시작했다는 안내까지 기다린다.
3. PC OOK 탭에서 평소처럼 실제 Tx와 카메라 상태를 확인하고 **비교 ID**에 같은 `a12-000`을 입력한 후 **고정각 수신 · 12 ms × 30회**를 누른다. 시작 신호 0 이후 1~30번이 2.5초 간격으로 송신된다. PC에서 약 78초 후 `completed`와 GPIO OFF 확인이 뜬 다음 Rx 터미널에 `DONE`을 입력한다. PC가 중단됐으면 Rx에서도 Ctrl+C로 끝낸다.
4. 같은 순서로 오프셋 **15°, 30°, 45°, 60°, 75°, 90°**를 측정한다. 예컨대 30°는 Rx에서 `--angle 30 --pair a12-030`, PC에서 비교 ID `a12-030`이다. 매 각도에 고유 ID를 쓴다. 마지막 성공 지점과 성공률이 떨어진 지점 사이만 5° 간격으로 추가 측정한다. 2번 실험과 같은 방향의 한쪽 범위를 측정하는 설계다.

| 입사각 오프셋 | 0° | 15° | 30° | 45° | 60° | 75° | 90° |
|---|---:|---:|---:|---:|---:|---:|---:|
| Pan 명령 | 180° | 165° | 150° | 135° | 120° | 105° | 90° |

**판정.** 각도별 30개의 고유 순번을 분모로 삼는다. 시작 신호까지 안 들어오는 각도도 기록한다. 송신 완료 로그와 Rx 전체 기록 구간이 확인된 상태에서 30개를 전부 놓치면 0/30이다. 샘플 공백 등으로 판정할 수 없는 명령은 따로 표시한다. 실험 중 PC와 Rx에 입력한 ID와 시작·종료 순서가 일치해야 서로 다른 시계로 기록한 파일을 대응시킬 수 있다. 정면에서 30/30이어도 다른 각도의 수신률은 새로 측정해야 한다.

**결과 모으기.** 각 Rx 실행 폴더는 `captures/M6-4/angle_…/`에 생긴다. PC 저장소의 같은 위치로 복사해 PC 송신 기록과 함께 둔다. PC에서 `python tools/analysis/angle_series.py --prefix a12-`를 실행하면 각도별 명령 수신률, 누락·판정 불가 횟수와 결과 그래프를 얻는다. 그래프에는 Matplotlib이 필요하다. 두 속도를 비교하려면 같은 배치에서 50 ms/bit(20 bit/s)도 별도 ID로 반복한다. 그때는 Rx에 `--bit-ms 50 --period-s 4`를 더하고 PC에서 비트 50, 간격 4, 마지막 단계 30, 조건 A로 **반원 2번 · 광프레임 송신**을 사용한다. 고정각 Rx 프로그램을 쓰므로 셀은 그 자세에 머문다.

## 무엇을 측정하나

고정된 광원 앞에서 PV 셀의 방향을 1°씩 바꿀 때, 수신기가 **실제로 받은 광명령**으로 각도를 보정하면 같은 가상 위치에서 셀 단자전압이 얼마나 달라지는지 측정한다. 물리적인 Tx와 Rx 발판은 한 자리에 둔다. Rx의 Pan 한 축으로 위치 변화에 따른 방향 변화와 그에 대한 보정을 합성한다. 이 시험이 재현하는 것은 입사 방향의 변화다. 실제 반원 이동, 비행 진동, 거리 변화나 Tx의 추적 성능은 측정 범위 밖이다.

| 항목 | 첫 실험 제안값 |
|---|---|
| 가상 반원의 반경 | 5.00 m. 실제 광원–셀 거리도 별도로 재서 기록 |
| 가상 진행각 | 180°, 179°, …, 0°. 180번 이동, 시작점 포함 181개 자세 |
| 1° 간격 | 4.00 s, 각속도 크기 0.25°/s |
| 등가 선속도 | 0.02182 m/s, 약 2.18 cm/s |
| 초기 자세 | Pan S0 명령 180°, Tilt S1 명령 20° 고정 |
| 광명령 속도 | 50 ms/bit = 20 bit/s. 이 조립 상태의 예비 시험값 |
| 기록 | INA219 3번 버스, 주소 `0x40`, 목표 샘플 간격 5 ms |
| 소요 시간 | 첫 자세에서 마지막 자세까지 12분. 마지막 측정 구간까지 한 번에 약 12분 4초, A+B 약 24분 8초. 준비·재정렬 시간 별도 |

반경 5 m에서 1°에 해당하는 호 길이는 `5 × π / 180 = 0.08727 m`다. 이를 한 단계 시간으로 나누면 등가 선속도가 나온다. 실험자가 장치를 들고 이 속도로 걸을 필요는 없다. 예를 들어 같은 반경에서 6초마다 1°를 움직이면 0.01454 m/s이고 한 방향 진행에 18분이 걸린다. 속도를 바꾸면 **PC와 Rx 양쪽의 단계 시간**을 같이 바꾼다. 광명령, 점등 측정, 송신 종료까지 한 단계 안에 들어와야 한다.

## 발판과 시작 방향

1. Tx와 Rx를 같은 높이에 고정하고, Rx의 회전축 가까이에 셀 중심을 둔다. 발판 위치, 광원 높이, 실제 거리, 주변광, 셀의 부하·배선 상태를 A/B에서 유지한다. 실내 고정 광원과 빔 종단을 사용한다.
2. 현재 조립품은 **발판 정면이 Pan 약 103°**, **셀이 수직인 Tilt가 약 20°**였다. 둘 다 기존 육안 관찰값이다. 이번 프로그램은 Pan 180°와 Tilt 20°를 지시한다. 첫 시험에선 서보의 초기 이동 여유와 케이블을 확인하고 PV를 지지한다.
3. 시작 자세에서 **발판 전체를 수평으로 돌려 셀 앞면이 고정 광원을 정면으로 보게** 한 뒤 발판과 책상에 기준선을 표시한다. 모터 축을 손으로 비틀지 않는다. 이 배치에서 Pan 180°가 광학 기준이 된다. 발판을 기존 103° 정면으로 둔 채 실행하면 시작부터 약 77°의 명령 오프셋이 생긴다.
4. 광원 세기·위치를 일정하게 두고 A/B 사이에 처음 표시한 위치로 돌아오는지 확인한다. 셀이 축에서 벗어나면 Pan 운동이 광점 위치도 바꾼다. 그런 경우 결과에는 입사각과 조명 면적의 효과가 함께 들어간다.

## A와 B는 어떻게 움직이나

두 조건 모두 시작 광프레임 0으로 시간을 맞춘다. 그 뒤 4초마다 Rx 자신의 시계로 기본 Pan 명령을 1° 줄인다. Tx는 같은 시간표로 같은 광프레임을 보낸다. 아래 각도는 모두 **서보 명령값**이다.

| 경과 | 가상 진행각 | A · 보정 끔 | B · 명령을 모두 수신한 경우 |
|---|---:|---:|---|
| 0초 | 180° | 180° | 180°로 동기 시작 |
| 4초 | 179° | 179° | 먼저 179°, 1번 프레임 수신 후 180° |
| 8초 | 178° | 178° | 먼저 179°, 2번 프레임 수신 후 180° |
| 308초 | 103° | 103° | 측정 구간에는 180° |
| 360초 | 90° | 90° | 측정 구간에는 180° |
| 720초 | 0° | 0° | 측정 구간에는 180° |

- **A · 보정 끔.** 광프레임을 읽고 도착 여부를 저장한다. Pan에는 기본 운동만 적용한다. 180°에서 정면으로 맞췄으므로, 90° 부근부터 셀의 옆면·뒷면으로 넘어가며 수신이 끊길 수 있다. 이것도 결과에 남긴다.
- **B · 광명령 보정.** 같은 기본 운동을 적용하고, 해당 단계 번호와 오류 검사에 맞는 광프레임을 받았을 때만 반대 방향으로 1°를 더한다. 예를 들어 2번 명령을 놓치면 해당 단계 측정각은 179°다. 3번 명령을 받아도 그 단계의 1°만 보정하므로 그 뒤 측정각도 179°다. 누락을 추측하거나 뒤늦게 몰아서 보정하지 않는다.
- 두 조건의 전압 차이는 **같은 가상 진행각**에서 계산한다. B의 최종 명령이 이상적으로 계속 180°더라도 매 단계 먼저 기본 −1° 이동이 일어난다. 각도 인코더가 없어 도착과 정착은 육안 또는 별도 측정으로 확인한다.

## 한 단계에서 전압을 읽는 시점

기본 설정에서 한 단계는 4초다. 각 단계의 광프레임 첫 비트 기준 시간표는 아래와 같다.

| 구간 | 무엇이 일어나나 |
|---|---|
| 0.00–1.60초 | 32비트 광프레임 송신. Rx가 동기 단어, 순번, CRC를 검사 |
| 1.60–2.10초 | 광원 연속 ON. B는 유효 명령을 적용하고 대기 |
| **2.10–2.70초** | **같은 밝기로 켜진 0.60초 구간의 셀 전압을 A/B 모두 평균**. 5 ms 간격이면 약 120샘플 |
| 2.70–2.90초 | 연속 ON 종료 여유 |
| 2.90–4.00초 | OFF 및 다음 프레임 준비 |

감지된 프레임은 Rx가 추정한 광프레임 시작 시각을 쓴다. 프레임을 놓쳤을 때도 가상 운동은 진행하고 같은 예정 구간에서 측정하되 `scheduled`로 표시한다. 광신호의 ON/OFF 전체 평균을 내면 명령의 비트 패턴 자체가 전압 차이에 섞인다. 이 설계는 두 조건에 같은 파형을 사용하고 연속 점등 구간을 비교한다. 0.50초 대기는 제안한 여유 시간이며, 첫 짧은 시험에서 1° 이동 뒤 셀이 계속 떨리거나 전압이 안정되지 않는지 살핀다.

## 실행 순서

### 1. 7속도 × 30회 종료 후 준비

1. 기존 OOK 실험의 종료·분석 저장을 확인하고 PC OOK 탭의 **연결 해제**를 누른다. 해당 Rx 수신기가 SSH로 연결된 동안 INA219 버스를 점유한다. 별도로 실행한 `pv_voltage.py --live`도 종료한다. VS Code의 Rx SSH 창은 계속 사용한다.
2. **PC VS Code 터미널**에서 원래 `Dynamic_OWPT_System` 저장소의 `M6-4`를 업데이트한다. 기존 Controller 창을 정상 종료한 뒤 같은 Python 환경에서 다시 실행한다. 평소 실행할 때 `--server`로 지정한 서버가 있으면 그 값을 그대로 사용한다.

```text
git pull --ff-only origin M6-4
python -m Tx.Controller.Com_main
```

3. **Rx VS Code SSH 터미널**에서 처음 내려받을 때는 아래 명령을 쓴다. 이미 같은 저장소가 있다면 해당 폴더에서 `git fetch origin`, `git switch M6-4`, `git pull --ff-only origin M6-4`를 실행한다.

```bash
git clone --branch M6-4 --single-branch https://github.com/leontnhaps/Dynamic_OWPT_System.git ~/Dynamic_OWPT_System
cd ~/Dynamic_OWPT_System
python3 -m Rx.arc_bench plan
```

4. Rx의 `i2cdetect -l`에서 3번 버스를 확인한다. 빠져 있으면 현재 배선(SDA GPIO17/물리 11번, SCL GPIO27/물리 13번)에 맞춰 `sudo dtoverlay i2c-gpio bus=3 i2c_gpio_sda=17 i2c_gpio_scl=27`를 한 번 적용한다. `sudo i2cdetect -y 3 0x40 0x40`에서 `40` 응답을 확인한다. Pan/Tilt HAT는 1번 버스에 둔다. Tx Pi는 기존 OOK 송신 서비스를 사용한다.

### 2. 5° 예비 시험

Rx 터미널에서 아래 한 줄로 시작한다. `START`를 입력하면 서보가 시작 자세로 이동한다. 발판을 정렬한 후 Enter를 누르고 **광학 동기 대기** 문구를 확인한다.

```bash
python3 -m Rx.arc_bench corrected --steps 5 --pair pilot01
```

PC의 **OOK 속도 (M4-4 · M6-4)** 탭에서 **카메라 시작 / 상태 조회**로 준비하고, 반원 실험의 `비트(ms)=50`, `1° 간격(s)=4`, `마지막 단계=5`로 맞춘다. 비교 ID는 `pilot01`, 조건은 B로 맞추고 **반원 2번 · 광프레임 송신**을 한 번 누른다. 시작 프레임과 1–5번을 모두 받았는지, 각 단계에서 Pan이 179°로 갔다가 180°로 돌아오는지, 점등 구간 전압이 기록되는지 본다. 마지막 자세 기록까지 약 24초다. 양쪽의 속도와 단계 수는 같아야 한다.

### 3. 본 실험

PC의 마지막 단계를 **180**으로 되돌린다. 아래 두 Rx 명령은 각각 **별도의 실행**이다. 각 실행마다 시작 자세를 확인한 후 PC에서 같은 비교 ID와 해당 A 또는 B를 선택하고 광프레임 송신을 한 번 누른다. 예비 시험과 본 실험의 ID를 구분한다.

| 순서 | Rx SSH 터미널 명령 | PC 설정 |
|---|---|---|
| A | `python3 -m Rx.arc_bench baseline --pair pair01` | `pair01`, A, 50 ms, 4 s, 180 |
| B | `python3 -m Rx.arc_bench corrected --pair pair01` | `pair01`, B, 50 ms, 4 s, 180 |

진행 중에는 발판, 광원 방향, 셀 부하를 유지한다. 중단할 때는 **PC의 레이저 OFF / 시험 중지**와 **Rx 터미널의 Ctrl+C**를 모두 사용한다. 송신을 중단해도 이미 시작한 Rx의 가상 운동 시계는 독립적으로 진행한다. 중간 중단은 기록에 남기고 새 ID로 다시 측정한다. 반복 비교를 할 때는 다음 쌍을 B→A 순서로 수행하면 시간에 따른 드리프트를 살피기 쉽다.

### 4. 결과 확인

- Rx의 `captures/M6-4/arc_…_baseline/`, `arc_…_corrected/`에 실행 설정과 종료 상태(`manifest.json`), 단계별 전압·Pan·프레임 검출(`steps.csv`), 원시 전압(`samples.csv`), 광프레임 수신 기록(`frames.csv`), 서보 명령과 I²C 쓰기 시각(`commands.csv`)이 남는다. PC의 `captures/M6-4/arc_tx_*.jsonl`에도 실행별 송신 기록이 생긴다.
- Rx 저장소 루트에서 `python3 tools/analysis/arc_voltage.py --pair pair01`로 두 실행을 묶는다. 같은 ID에 완료된 A와 B가 하나씩 있어야 한다. 송신까지 검증할 때는 PC에서 두 Rx 실행 폴더를 같은 `captures/M6-4/`로 복사하고 `--tx-a`와 `--tx-b`에 각각 해당 PC 송신 로그 경로를 지정한다.
- 분석 폴더의 `angles.csv`는 같은 진행각에서 A와 B의 전압과 차이 `B−A`를 보여 준다. `comparison.json`은 비교 가능한 각도 수와 프레임 누락을 함께 집계한다. Matplotlib이 설치된 환경에서는 `voltage.png`도 생긴다. 보고할 때는 전체 비교 가능 각도의 결과와 **양쪽 모두 프레임·측정 구간이 확인된 부분집합**을 함께 제시한다. 프레임이 약해지는 후반 구간을 빼면 A/B 차이가 달라질 수 있다.

**판독 기준.** 먼저 시작각에서 A와 B의 전압이 재현되는지, 이후 B의 보정 명령이 실제로 수신됐는지, 그 뒤 같은 각도에서 전압이 얼마나 달라졌는지를 순서대로 본다. B의 전압이 더 클 것이라는 가설은 측정 결과와 구분한다. 계측값은 이 부하 조건의 셀 단자전압이다. 전력이나 변환 효율을 보고하려면 같은 부하에서 전류도 측정해야 한다.

부품 사양은 [Waveshare Pan-Tilt HAT](https://www.waveshare.com/wiki/Pan-Tilt_HAT)와 [TI INA219 데이터시트](https://www.ti.com/lit/ds/symlink/ina219.pdf)를 참조한다. S0=Pan, S1=Tilt 배정과 약 103°·20° 기준은 이 조립품의 관찰값이다.
