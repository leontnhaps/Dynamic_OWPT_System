# 실전 · YOLO + SAC 탭

기존 Server / Raspberry Pi 연결과 `Com_main.py` GUI를 그대로 사용한다. 기본 추적은 PC에서 YOLO 검출과 고정된 SAC 정책 추론을 수행한다. 별도 `학습 시작 (지정 횟수)` 버튼으로 SAC 추가 학습을 선택할 수 있다(아래 설명). M0 문서는 변경하지 않는다.

## 실행

Windows VSCode 터미널, 프로젝트 루트:

```powershell
& "C:\Users\gmlwn\anaconda3\envs\PTCamera_wavehsare_gpu\python.exe" Tx/Controller/Com_main.py --server <서버IP>
```

기존 서버를 실행하고 Pi는 기존처럼 `python Tx/RaspberryPi/Rasp_main.py --server <서버IP> --servo-port /dev/serial0`으로 연결한다. 기존 CUDA 환경의 torch를 재설치할 필요 없다. GUI에 필요한 Pillow와 학습에 사용한 numpy/gymnasium/stable-baselines3, YOLO에 사용한 ultralytics가 같은 PC 환경에 있어야 한다. 실전 탭의 모델 불러오기 전에는 ML 패키지를 import하지 않으므로 기존 탭은 그대로 사용할 수 있다.

1. Camera 탭: 선택할 SAC 모델 config의 해상도(현재 1296×972)로 영상 수신. fps 목표 10. 레이저 기준점도 config 값을 그대로 사용한다. 실측 기준점과 다르면 해당 config 사본에 실측 좌표를 넣어 별도로 선택한다. 잘못된 해상도를 자동 확대/축소해서 정책에 넣지 않는다.
2. Pan / Tilt 탭: 상태 조회 → 운용 범위 입력·적용 → Pan/Tilt 0°, 0° 입력·이동 완료 응답 확인. 현재 모델의 범위는 Pan -180~180, Tilt -15~40. 실제로 적용한 더 좁은 범위를 벗어나는 추적 명령은 자동 제한해 계속 추적하지 않고 중단한다. SPD/ACC는 이 탭의 입력값을 사용한다.
3. 실전 탭: YOLO best.pt, SAC model.zip(또는 체크포인트), **그 SAC를 학습한 config.json** 선택. SAC 선택 시 인접 config 또는 체크포인트 상위 폴더 config를 자동 찾는다. cpu/cuda, PV class ID, confidence를 설정하고 모델 불러오기. class 이름 목록과 해상도/레이저 기준점이 표시된다. 다른 학습 run의 config를 섞지 않는다.
4. 검출 + SAC 출력 보기: 추론을 워밍업하고 녹색 PV 박스/중심, 빨간 레이저 기준점, 오차와 원래/적용 Δ각도를 확인. 이동은 전송하지 않는다. 직전 명령이 없을 때 미리보기 계산만 (0,0)을 가정한다.
5. 추적 시작: 현재 알려진 **직전 명령각**에서 시작하며 자동 영점 이동은 없다. YOLO와 SAC가 함께 동작하고 실제 명령을 전송한다. 첫 테스트는 레이저 OFF 상태에서 Pan/Tilt 움직임을 확인한다. 학습 모델의 추적 성능/실제 축 부호는 보장하지 않는다.
6. 정지: 추가 명령 전송을 중단한다. 추론 중인 이전 결과도 폐기한다. 이미 전송한 명령을 취소하거나 기계적으로 즉시 정지시키는 기능은 아니다. Pi serial write 응답도 실제 각도/도달 피드백이 아니다.

## 제어 및 기록

- 원본 영상 좌표 → PV 중심−laser → `simulation.control.encode_observation` → deterministic SAC → `absolute_command` 재사용. Δ ±5°, 1° 반올림과 누적 명령은 학습과 동일하다. 관측은 영상 오차/차분/직전 명령 6개이다.
- 제어 목표 간격은 config.dt(0.1초). 실제 간격은 영상 수신/추론/응답 지연에 따라 길어진다. 최대 한 건만 추론하고, 한 건의 이동 응답을 기다린 뒤 새 프레임으로 다음 추론을 한다. 응답은 실제 도달을 의미하지 않는다.
- 미검출/동일 class 다중 검출, 0.5초 이상 지난 수신 프레임/추론 결과, 연결 변경, 서보 오류/응답 시간 초과, 운용 범위 이탈은 자동 중단한다. 재검출되더라도 사용자가 다시 시작해야 한다. 영상 나이는 PC 수신 기준이며 Pi 촬영부터의 전체 지연은 아니다.
- 수동 이동/범위/영상 설정 명령은 실전 추적을 중단한다. 이동 응답 대기 중에는 다른 이동을 막는다. 레이저를 자동 ON하지 않는다.
- `captures/M4/live/<실행시각>/session.json`: 선택 모델 경로, config, 운용 설정.
- `frames.csv`: 프레임 ID, 수신 후 경과시간, 추론시간, 오차, 원래 Δ각도, 적용 Δ각도, 목표 명령각, request ID, sent/hold/missing 상태.
- 기존 GUI events JSONL에는 명령 및 응답, live_start/stop/error가 기록된다. 정지 이유는 여기에 있다. 위치 오차는 검출 좌표 기준이며 실측 서보각/전력은 기록하지 않는다.

## SAC 추가 학습 (에피소드 단위)

새 `학습 시작 (지정 횟수)` 버튼은 저장된 SAC 가중치/optimizer에서 실제 경험으로 추가 학습한다. YOLO 가중치는 업데이트하지 않는다. 기존 `추적 시작` 버튼은 학습 없는 평가 모드다. 모델을 불러온 뒤 먼저 미리보기로 YOLO를 워밍업하고 정지한 다음 학습을 시작한다.

### 에피소드 진행

1. 입력한 초기 Pan/Tilt min~max 안에서 정수 각도를 균일하게 추첨한다. 기본 각 축 -1~1°. 이 범위는 **초기 위치만** 제한한다. 추적 동작에는 기존 Pan/Tilt 탭의 운용 범위와 모델의 범위를 적용한다. 범위를 벗어나는 명령은 중단한다.
2. 무작위 초기 명령 전송 → Pi 전송 응답 → 기본 1초 대기. 이 응답/대기는 실제 도달 측정이 아니다. 초기화 이동은 SAC 행동/경험에 넣지 않는다.
3. 대기 후 새 프레임부터 YOLO 검출 및 에피소드 시계 시작. 최대 20초(변경 가능). 최초 미검출에서도 이전 좌표로 움직이지 않는다.
4. SAC는 학습 모드에서 확률적으로 탐색한다. 기존 모델은 해당 config의 Δ 범위를 사용하고, 새 모델은 기본 ±1°/1° 명령을 사용한다. 추론과 네트워크 응답은 이전처럼 최대 한 건씩 처리한다. 새 관측으로 직전 행동의 결과를 연결하고 config의 `reward_terms`를 계산한다. 실제 step 간격은 지연에 따라 달라지고 경험에 기록된다. 현재 gamma는 시간 간격별 보정 없이 전이당 적용한다.
5. 첫 미검출부터 추가 이동을 보류한다. 기본 3회 **연속 처리 프레임** 미검출 또는 첫 미검출 후 0.5초 경과 중 먼저 도달하면 `target_lost`로 종료한다. 유효 검출이 돌아오면 카운터를 초기화하고 새 관측에서만 제어한다. 다중 PV는 설정한 클래스·confidence 하한을 통과한 유효 후보 중 최고 confidence 하나를 선택하고 계속한다. 동점이면 검출 순서상 첫 후보를 선택한다. 오래된 영상/추론, 연결/응답 오류도 종료한다.
6. 에피소드 경험 저장 → SAC 업데이트 → 모델/버퍼 저장 → 1초 대기 후 다음 초기 자세로 이동한다. 지정 횟수(기본 10회)만큼 반복하며, 횟수 1이면 단발 실행이다. 시간 제한과 target_lost만 다음 에피소드로 이어진다. 사용자 정지·통신/서보 오류·오래된 영상·저장 오류는 전체 반복을 취소한다. 중앙에 도달한 것만으로 끝내지 않아 정렬 유지도 경험할 수 있다.

### 보상과 종료 처리

- 검출 중 reward는 불러온 config의 조준 항 및 명령 비용을 그대로 사용한다. `command_weight=0`이면 조준 항만 남는다. 새 SAC 생성 시에는 아래 정렬 보상을 사용한다.
- 미검출 종료에는 화면 밖 실제 오차를 알 수 없으므로 별도 terminal reward `-loss_penalty`를 사용한다. 기본 -10, UI에서 0 이상 입력. 이는 새로 추가된 실패 종료 비용이며 시뮬레이터의 화면 밖 GT 제곱 오차가 아니다.
- terminal sample의 next observation은 형식을 위한 placeholder일 뿐이며 `terminated=True`로 bootstrap을 막는다. 이 좌표는 제어에 사용하지 않는다.
- 시간 제한은 `truncated=True`로 처리해 다음 상태 가치 추정을 유지한다. 사용자 정지/통신 오류/시간 종료 시 아직 관측되지 않은 마지막 행동은 임의 보상을 만들지 않고 버린다. 마지막으로 완료된 전이는 truncation으로 경계를 기록한다. 초기 미검출로 유효 행동이 없으면 terminal 경험도 만들지 않는다.
- 실물 제어 경험에는 촬영 시각과 실제 도달각이 없으므로, PC 수신시각과 Pi의 명령 전송 응답을 기준으로 연결한다. 엄밀한 모터 동역학 식별이나 지연 보정이 완료된 상태는 아니다.

### 업데이트·파일

- 새 모델 로딩 후 첫 학습 실행은 새 **실제 경험 버퍼**(50,000개)를 만든다. 시뮬레이션 버퍼를 섞거나 자동 불러오지 않는다. 같은 실행 중 다음 에피소드는 버퍼를 유지한다.
- 유효 경험 64개 이상이면 종료마다 기본 32 gradient update, batch 64. 경험이 부족하면 저장만 하고 다음 에피소드에서 누적한다. learning rate/entropy 설정은 로드한 SAC를 따른다.
- 업데이트는 추론과 같은 단일 worker에서 수행하고 제어는 멈춘다. 정지 버튼은 추가 업데이트를 중단하고 현재 상태를 저장한다. 원본 모델 파일은 덮어쓰지 않는다.
- 저장 위치: `captures/M4/live_training/<시각>/episode_0001/` 등.
  - `model.zip`, `config.json`, `replay_buffer.pkl`: 에피소드 후 정책과 버퍼.
  - `transitions.jsonl`: 관측, 원래 정규화 행동, 다음 관측, reward, terminated/truncated, 실제 관측 여부, 전이 간격.
  - `summary.json`: 종료 이유, 보상합, 전이 수, 버린 미완료 행동 여부, 업데이트 수, 누적 버퍼 수, 초기 각도와 설정.
- session 폴더에는 원본 모델 경로/난수 seed와 optimizer 로그가 있다. 기존 live 프레임 CSV 및 GUI events 기록도 함께 생성된다. GUI events에 각 폴더 경로가 기록된다.
- 저장 모델은 기존 실전 탭에 불러와 학습 없이 평가할 수 있다. 다른 실행에서 그 모델로 추가 학습을 시작하면 가중치는 이어지고 실제 버퍼는 새로 만든다. 저장 버퍼의 자동 복원 UI는 이번 버전에 포함하지 않는다.

검증: 기존 live 테스트와 `test_online_learning.py`의 초기 범위, 다음 관측 보상 연결, 연속 미검출 중 명령 미전송, 종료 마스크, 사용자 정지, 실제 SAC optimizer 갱신 및 저장/재로딩 테스트. 실물 카메라/모터에서 수행한 학습 성능 검증은 아니다.


## 정지 PV에서 SAC 처음부터 학습 / 연속 실행

1. Camera 영상을 수신하고 Pan/Tilt 상태·운용 범위·알려진 시작 명령각을 준비한다.
2. YOLO `best.pt`를 선택한다. SAC 파일은 필요 없다. config는 공란이면 기본값, 선택하면 해상도/보상/행동 등 아래 재정의 항목 외의 설정 템플릿으로 사용한다. 기존 SAC 가중치는 읽지 않는다.
3. 하단 **SAC 처음부터 학습**에서 실측 레이저 기준점 `u,v`를 입력한다. 표시 기본값 `(696,384)`는 기존 설정값이며 자동 보정값이 아니다. 실제 해상도/거리/보정과 일치하는지 반드시 확인한다. 영상 중심으로 대체하지 않는다.
4. `1회 최대 Δ` 기본 1°, `보상 반감 거리` 기본 50 px. 장치 cpu/cuda 선택 후 **YOLO + 새 SAC 생성**을 누른다. 생성은 이동을 발생시키지 않는다. 버튼을 다시 누르면 학습된 가중치도 새로 초기화된다. 매 에피소드마다 누르지 않는다.
5. **검출 + SAC 출력 보기**에서 녹색 PV와 빨간 기준점을 확인 → **정지** → 진행 중 추론 완료를 기다린다.
6. 시작 범위는 Rx가 보이는 자세 주변 ±1°부터, 20초, 반복 횟수 10, 업데이트 32로 **학습 시작 (지정 횟수)**를 누른다. 초기 자세 범위와 추적 운용 범위는 별개다. 설정은 한 배치 시작 때 고정되고 도중 UI 변경은 다음 배치부터 적용된다.
7. 매 회 저장한 뒤 같은 정책과 경험 버퍼로 이어 학습한다. 유효 경험 64개 전에는 optimizer 업데이트 없이 경험만 누적한다. 회차와 누적 경험/업데이트/종료 사유를 확인한다. **정지**는 저장 중·에피소드 사이 대기 중에도 다음 자동 이동을 취소한다.
8. 저장한 `model.zip` + 같은 폴더 `config.json`을 기존 **모델 불러오기**로 열어 **추적 시작**하면 탐색 없는 평가를 할 수 있다.

새 모델은 `reward_mode=alignment`, `pointing_weight=10`, `command_weight=0`, `scenario=stationary`를 저장한다. 행동 후 검출한 PV 중심과 레이저 기준점의 유클리드 픽셀 거리 `d`로 `r=10/(1+d/50)`을 계산한다. 0/50/100/200 px에서 각각 10/5/3.33/2점이며, 미검출 종료는 별도 기본 -10점이다. 수신전력은 보상에 포함하지 않는다. 사용자가 거리값을 바꾸면 50 대신 그 값을 사용한다. 이전 config에는 새 필드가 없어도 기존 제곱 오차 보상을 유지한다. 평가·시뮬레이션 코드도 저장된 reward_mode를 읽는다.

새 SAC: MLP [128,128], 학습률 3e-4, batch 64, 실제 버퍼 50,000, SAC 기본 자동 entropy 조정. 탐색은 초기 무작위 신경망의 확률적 정책을 사용한다. 모양 정의만을 위한 환경을 만들며 시뮬레이션 reset/step으로 사전학습하지 않는다. 10회는 동작 확인용 횟수이며 수렴을 보장하지 않는다. 변경한 ±1° 행동 범위 모델에 기존 ±5° 모델 가중치를 끼워 넣지 않는다.

M4 결과는 `captures/M4/live_training/<시각>/episode_0001/` 아래 저장된다. M3 기존 결과는 이동하거나 덮어쓰지 않는다. 서보 응답은 명령 전달 응답이고 실제 도달 피드백이 아니며, 행동 후 관측의 지연 한계는 기존과 같다. 실물 학습 성능은 현장 검증이 필요하다.

검증: `python -m unittest discover -s tests -p 'test_live*.py' -v` 및 `python -m unittest discover -s tests -p 'test_online_learning.py' -v`.


## 다중 검출 선택 및 좌표 로그

PV 후보가 여러 개면 최고 confidence 하나를 선택한다. 미리보기·평가·학습 모두 같은 규칙을 사용한다. 유효 후보가 0개일 때의 기존 미검출 처리는 유지한다. 실제 표적 ID를 추적하는 방식은 아니므로 프레임 사이에 선택이 바뀔 수 있다.

`frames.csv`에 `detection_count`(필터 후 후보 수), `selected_confidence`, `pv_u`, `pv_v`를 추가했다. 미검출 행은 후보 수 0, confidence/좌표는 공란이다. 기존 `command_pan/tilt`는 실제 측정각이 아닌 목표 명령각이다. 이번 변경에서 보상식은 변경하지 않았다.


## 50 px 안쪽 추가 보상

새 SAC 생성은 기본 `alignment_bonus=30`, `alignment_bonus_radius_px=50`을 사용한다.
기본 역수형 항과 합쳐 `r=10/(1+d/50)+30*max(0,1-d/50)^2`이다. 새 모델의 보상 반감거리 입력은 **기본 역수형 항에만** 적용하며 추가 보상 반경은 별도 50 px다. 전체 보상의 반감거리를 의미하지 않는다.
거리 100/50/25/10/0 px에서 보상은 3.33/5/14.17/27.53/40이다. 행동 후 관측으로 계산하고 정렬 도달 시 종료하거나 일회성 성공 보상을 주지는 않는다. 미검출 종료 벌점은 유지한다.

기존 모델로 이어가려면 저장 완료 후 GUI 재실행 → 최근 model.zip/config.json 불러오기 → **현재 SAC에 50px 추가 보상 적용** → 학습 시작을 누른다. 이 버튼은 역수형 거리 50, 최대 기본점수 10, 명령비용 0, 추가점수 30, 추가반경 50으로 설정한다. 가중치/optimizer와 레이저 좌표/행동 범위는 유지하고, 이전 보상으로 저장된 경험이 섞이지 않도록 버퍼와 학습 세션을 새로 시작한다. 이미 동일 설정이면 버퍼를 초기화하지 않는다. 새 세션의 config.json 및 체크포인트 config.json에 새 설정이 저장된다.

이전 config에 추가 보상 필드가 없으면 기본값은 0이므로 자동으로 보상이 변경되지 않는다. 이어 학습하려면 위 버튼을 눌러야 한다. 기존 저장 파일은 덮어쓰지 않는다. 전체 보상이 커졌으므로 기존 보상합과 새 보상합을 직접 비교해 성능 향상으로 해석하지 않는다.
